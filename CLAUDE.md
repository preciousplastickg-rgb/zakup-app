# Подотчёт закупщика — PWA для Азия Стали

Личный инструмент учёта подотчётных денег одного закупщика. Он ездит по строительным рынкам и закупает стройматериалы и материалы для производства. Приложение фиксирует выданный аванс и каждую закупку, показывает остаток и формирует авансовый отчёт для бухгалтерии.

Полное ТЗ: https://claude.ai/artifact/ApvaidaDdTu6HiBAaJctWG
Кликабельный прототип UI: `prototype/index.html` (демо на localStorage; это эталон интерфейса и логики, а не продакшн-код).

## Контекст

- Один пользователь. Ролей, согласования, сервера и кабинета бухгалтера нет.
- Все деньги выдаются авансом. Покупок на свои деньги с компенсацией нет, поэтому баланс один: остаток подотчёта.
- Бумажные чеки и накладные сдаются в бухгалтерию физически. Фото — резервная копия.
- Связка с бумагой: каждая закупка получает сквозной номер (001–999 в пределах года), закупщик пишет его ручкой на чеке.
- Валюта только KGS.
- Отчёт нужен закупщику (контроль остатка) и бухгалтерии (Excel и PDF).

## Платформа (решено, не пересматривать без причины)

- PWA без бэкенда, бюджет 0. Нативный iOS отклонён из-за Apple Developer ($99 в год), AppSheet — из-за лицензии (бесплатный план только для non-business).
- Vanilla JS, без сборки: `index.html` + `manifest.json` + `sw.js` + `app.js` + `db.js` + `reports.js`. Тяжёлые библиотеки (SheetJS, jsPDF, JSZip) грузятся при первом отчёте, а не при запуске.
- IndexedDB через Dexie.js. При старте вызывать `navigator.storage.persist()`.
- Excel — SheetJS. PDF — jsPDF + autotable, файл формируется в приложении и отдаётся через «Поделиться». `window.print()` отклонён: в установленном на iPhone PWA он ненадёжен, а проверить его можно только на устройстве.
- Бэкап — JSZip (`data.json` + `photos/`), отдача через `navigator.share`.
- Хостинг — GitHub Pages (HTTPS обязателен для service worker и камеры).
- Целевое устройство — iPhone, iOS 16+, Safari, установка через «На экран Домой».
- Все библиотеки локально в репозитории (vendor/), чтобы service worker кэшировал их для офлайна. Без CDN в рантайме.

## Обязательные технические правила

1. Деньги — целые числа в тыйынах (`125050` = 1 250,50 KGS). Никаких float в суммах. Форматирование только при выводе. Сумма позиции считается функцией `itemSum` через целые тысячные (`Math.round(qtyMilli * price / 1000)`), где qty — число с 3 знаками, price — в тыйынах.
2. Схема Dexie версионируется с первого коммита: `db.version(1).stores({...})`. Каждое изменение схемы — новая версия с `.upgrade()`. Версия схемы пишется и в бэкап.
3. Номер закупки выдаётся внутри транзакции `db.transaction('rw', db.purchases, db.counters, ...)`. Кнопка «Сохранить» блокируется на время записи (двойной тап).
4. Фото хранятся как `Blob` в IndexedDB, не base64. Сжатие до записи: canvas, 1600 px по длинной стороне, JPEG 0.7.
5. Остаток нигде не хранится, а всегда считается: `Σ выдач − Σ активных закупок − возврат`.
6. Тестировать в установленном режиме (с экрана «Домой»), а не во вкладке Safari: хранилища разные.

## Бизнес-правила

- Одновременно открыт один подотчётный период (номер `П-2026-07`). Повторная выдача добавляется в текущий.
- Удаления закупок нет, только сторно с обязательной причиной. Номер после сторно не переиспользуется. Сторно — отдельный блок отчёта, в сумму не входит.
- В открытом периоде правка свободная, каждое изменение пишется в журнал (сущность, id, поле, было, стало, время).
- Закрытый период не редактируется. Исправление — только переоткрытие с причиной, отчёт получает пометку «редакция N».
- Закрытие только вручную: по исчерпании аванса или по запросу бухгалтера. Расписания и привязки к календарю нет, даты периода — от открытия до закрытия.
- Закрытие: предупреждение о закупках без позиций (не блокирует), подтверждение сдачи бумажных документов, ввод возврата (не больше остатка), обязательный бэкап перед закрытием.
- Перерасход: сохранение разрешено с предупреждением, остаток красный, в отчёте отдельная строка. Блокировки нет (решено).
- Тип документа обязателен: чек ЭККМ / товарный чек / накладная / ЭСФ / без документа. «Без документа» сохраняется после второго нажатия и идёт отдельным итогом.
- Быстрый режим закупки: сумма + поставщик, назначение/документ/оплата по умолчанию из последней закупки. Цель — ≤ 60 секунд и ≤ 5 нажатий.
- Позиции (наименование, ед., кол-во, цена, сумма) нужны для отчёта и вносятся позже, по чекам: из карточки сохранённой закупки, пока период открыт. На рынке закупка сохраняется без них; переключатель в форме из прототипа не переносим. Если сумма позиций расходится с суммой закупки, показать разницу; после подтверждения сумма закупки заменяется суммой позиций, изменение пишется в журнал.
- Фото: чек или накладная (`receipt`, одно, пересъёмка заменяет) и товар (`goods`, необязательно, несколько). Оба вида хранятся в `photos`.
- Единицы: шт, м, п.м., м², м³, кг, т, л, уп., лист, меш., рулон.

## Модель данных (Dexie stores)

```
periods:    ++id, number, status            // opened, closed, ret, revision
advances:   ++id, periodId, date            // amount, method(cash|transfer), by, comment
purchases:  ++id, &no, periodId, dt, supplierId, purposeId, status
            // place, amount, payment(cash|transfer), docType, comment, items[], stornoReason
photos:     ++id, purchaseId                // blob, kind(receipt|goods)
suppliers:  ++id, &name                     // place, phone, comment, archived
purposes:   ++id, &name                     // active
counters:   &key                            // { key:'purchase-2026', value:48 }
auditLog:   ++id, entity, entityId, at      // field, before, after
settings:   &key                            // userName, org, lastBackupAt
```

Уникальность `no` — в пределах года; если нумерация обнуляется в январе, индекс сделать составным `&[year+no]`.

## Отчёты

Утверждённой формы авансового отчёта у Азия Стали нет, отчёт в произвольной форме.

- Excel `Подотчёт_П-2026-07_2026-10-01_2026-10-31.xlsx`, листы: Сводка, Реестр, Позиции, Сторно.
- PDF A4 книжный: шапка (организация, ФИО, период, редакция), выдачи, реестр с позициями (наименование, кол-во, ед., цена, сумма) под каждой закупкой, итоги по назначениям, без документов, остаток/возврат/перерасход, строки подписей (подотчётное лицо, бухгалтер, руководитель). Фото документов — отдельным PDF-приложением, одно на страницу. Фото товара в PDF не входят.

## Бэкап

- `backup_YYYY-MM-DD.zip`: `data.json` (все таблицы + schemaVersion) и `photos/<year>-<purchaseNo>_<n>.jpg` (год обязателен: нумерация обнуляется в январе).
- Баннер на главной: > 7 дней или > 20 закупок с прошлого бэкапа.
- Восстановление — полная замена после подтверждения, без слияния. Файл проверяется целиком до изменений, замена идёт одной транзакцией. При смене схемы старые копии приводить к новой версии в `readBackup`.

## Этапы

1. Ядро: главная, выдача, быстрая закупка, остаток, фото. manifest + sw, офлайн.
2. Позиции в карточке закупки, справочники, сторно, журнал изменений.
3. Закрытие периода, отчёты Excel и PDF.
4. Бэкап и восстановление, деплой на GitHub Pages.
5. Пилот 2 недели параллельно с бумагой, сверка с бухгалтерией.
